The Order-1 Ledger

Every measurement and verdict from the 2026-08 order-1 entropy research on pivco-huffman and phaz — three merged session threads, one running document. All shipped coders roundtrip-verified byte-exact.

What this is about

  • A zstd-style compressed file is a few byte streams: literals, the ll/ml/of sequence codes (length/offset bucket ids), and raw extra bits.
  • zstd codes each stream with one table — order-0.
  • Everything in this ledger is one idea in different costumes: pick the table from something already decoded — the previous byte, the same sequence's other field, the last few bits.
  • The catch is never ratio — it is decode mechanics. Contexts must come for free (pre-decoded streams, table switches), never from adaptive coder state.

1 · The PR #30 proposal — dynamic nibble-FSE on the bitmaps

The proposal. PHA codes each PH node's partition bitmap with one of 50 static density tables (a 1-byte marker picks the table). PR #30 adds a transmitted alternative, wire id 51: recode the bitmap as nibbles and ship a per-node dynamic 16-symbol FSE table (NCount header), commit-if-smaller against the static menu. The small alphabet makes table transmission cheap; the transmitted table captures sequence structure in the nibble stream that a static order-0 density table cannot see.

2 · Carry-context coding — order-k tANS on the partition bitmaps

The idea. Bring order-1+ modeling inside PH itself, onto the partition bitmaps (Part II's literal and sequence-code threads reach the same idea from the stream side):

  • Model each bitmap byte as eight chain-rule steps of P(bit | previous k bits).
  • Only the 2^k probabilities go on the wire (2–32 B, quantized). Both sides expand them into 2^k static tANS tables over 256-value byte blocks.
  • The table for a byte is picked by the carry — the last k bits of the previous byte. Context costs a table-base index, not per-bit work. k is the model knob; byte width is just the speed knob.
  • Quad fusion extends it across tree levels: a node and its two children's bitmaps interleave into one stream of 2-bit route symbols (which child, then which grandchild). That restores the neighbour context that splitting into per-node bitmaps destroys. Fusion's own attribution: §4.

Method: KT-priced probes first (adaptive coder as the un-cheatable yardstick), coder second, containers third.

for j:
    e = T[carry][x]                    # one lookup decodes 8 bits
    out[j] = e.sym
    carry = rev_k(e.sym >> (8−k))
    x = e.base + read(e.nb)

Two bugs only pricing could catch (roundtrips stayed green): a carry bit-order mismatch (tables consulted under permuted context labels — 65 B streams ballooned to 3.5 KB), and the min-freq-1 floor (taxes skewed tables up to 256/2048 of the mass; cured by ESC).

3 · Carry-context coding II — the speed program (census, DP build, catalog, lanes, gating)

The idea. The ctx coder (§2) is ratio-proven but decode-poor; this section is the measured program that closes the gap. The census that frames it (instrumented build, dict-128, 12 L19 silesia files): 9,009 committed ctx nodes carry 48 KB of parameters using only 2,667 distinct sets; table builds cost 711.8 ms against 38.5 ms of actual decode loop — an 18:1 ratio even with the dictionary cap. Encoder side: 169,777 candidate encode passes for 19,892 commits (8.5×).

  • DP build factorization — LANDED (diff in explore/build_dp/): nibble-DP probability expansion, 1.09–1.30× full-build (quad modes gain most), 3.3–8× on the probs phase, wire-identical tables verified on 20,200 random parameter sets per mode, roundtrip green. The naive single-prefactor form flips normalize() floors on 1e-4..1.7e-3 of quad sets — the shipped variant keeps the high half bit-exact. Float probs: no speed gain, ~1% of quad sets drift — rejected as wire drift.
  • Canonical parameter-set catalog: 1-byte set ids (saves ~26 KB corpus wire) or a spec-predefined catalog (~39 KB, zero per-file builds, process-lifetime tables) — the structural fix for the 18:1 build ratio, extending §5's canonical p-levels and the pooled context maps.
  • G-lane lockstep decode: the ctx loop runs 5.6–6.8 ns/sym against the ~1.4 ns dependent-lookup floor — latency-bound, far under the M4 IPC wall. 4 lanes project 2.5–3×; navigates the old multi-cursor negative correctly (that loss was the bitmap walk, not ANS chains). Projected, not yet measured.
  • Encoder gating by closed-form pricing: histogram-priced candidates, real encode only for the argmin — cuts ctx compress ~5–8× (today ~10× PHA cost, attempt-dominated).
Verdict Catalog + lanes is the credible path from 0.6–0.9× to ~1× zstd-19 decode at unchanged ratio; the DP build is banked. id51 side notes: 6,412 nodes pay 13.7 B NCount each (107 KB line, repeat-mode plausible) and a per-node calloc + nibble-repack pass (fusable, est. 1–3 ms+ on mozilla).

The idea. A node and its two children's bitmaps interleave into ONE stream of 2-bit route symbols: which child, then which grandchild. 4.1 · Loose end: 3-level (oct) fusion — dead on applicability

Extend the route symbol to 3 bits (parent, child, grandchild). Probe: 8-ary KT at matched context memory vs the shipped form (quad at the parent + grandchild bitmaps coded separately), on every quad triple whose four grandchildren are all internal.

  • Applicability kills it first: 178 of 4,687 quad triples (3.8%) qualify — PH trees are leaf-heavy. Zero eligible on dna, csv, log, pride, xml, and both of-streams.
  • Where eligible, −1.36% of those triples' bytes = −18 KB corpus-wide ≈ 0.01% of output. Some cells lose outright (ml-mozilla +1.0% — the 8-ary alphabet dilutes context); the best relative cells (cat-wiki −11.2%, json −9.4%) are ~1 KB absolute.
  • Greedy validated in passing: parent bitmap + two child-level quads is +0.13% worse than quad-at-parent — parent-priority was the right call.
  • The probe requires full 3-level subtrees; a mixed oct/quad alphabet would apply wider, but −1.4% on the best-case set bounds it. An 8-cursor decode merge buys ~nothing → dead.

5 · Binary window walk & the PH-tree audit

The idea. A window-walk tANS decoder (§12's trick: widen the table index with the next W raw stream bits, so one lookup emits several symbols) on a binary alphabet — PH's partition bitmaps are Bernoulli(p) bit streams, so one entry can emit up to 32 bits packed in a word. The companion audit asks whether phaz's PH trees even produce bitmaps skewed enough to feed it. Roundtrip vs the honest baseline (byte-alphabet FSE over the packed bitmap — one step = 8 bits):

Crossover at p ≈ 0.85–0.88 on all four platforms. Shrinking the table (32 KB / 16 KB variants) always loses — at one hot p the 256 KB table’s active subset self-shrinks into L1, so explicit shrinking only cuts yield.

The audit that closed it Traffic-weighted PH-tree bias measurement: all six literal trees average bias 0.52–0.53 with zero bitmap bits at p≥0.625 — the Huffman tree is itself the de-skewing transform; routing bits are its near-uniform residue (H₀ ≈ 0.997 b/bit). De-skewing removes only the MARGINAL bias this coder needs — the serial structure in the same bits is real and large (§1.1's census: lit x-ray 0.68 b/sym), which is what §1/§2 harvest. Biased bitmaps exist only on dominant-symbol code trees (x-ray-ml: 92% of bits at ≥0.85), where symbol-level tANS (§12/§13) supersedes the whole PH+bitmap route. No phaz customer — but the canonical-p tables found one anyway, inside §14’s secondary coder.

6 · PH wire fixed-cost audit — K_right and marker bytes

The idea. Every non-leaf-only PH node record pays a raw 2-byte K_right header and a 1-byte FSE marker. Neither line had ever been itemized.

  • Markers in PH mode are 100% waste: constant 0, 1.6–3.4 KB/file = 0.05–0.18% of container. Dropping them is decode-FREE (fse_enabled is baked into the table both sides share).
  • The kr diet is declined: conditioned on the K bucket, kr is essentially incompressible beyond its natural width — KT, binary-KT and plain variable-width packing land within 2–4% of each other. Variable-width capture: 96–99% of the realizable diet, worth only 0.01–0.10% of container, and the per-node bit-unpack cost roughly cancels it at the walk-layer price (1 cyc/node ≈ 0.1% E2E).
  • Popcount-instead-of-kr is structurally unavailable in the BU wire: kr is consumed at pre-order to size children; the bitmap it would derive from sits at post-order, after them.
Verdict Fold marker-drop-when-FSE-off into the next planned wire revision; do not give it its own format break. Skip the kr diet. Total honest ceiling of both diets: 0.06–0.28% of container.

7 · Demux kernels — reconstructing order-1 literal streams

The idea. Order-1 literal coding splits bytes at encode into K streams, keyed by the previous byte's class (its top bits). Decoding must re-interleave them. The entry emits several output bytes at once, plus each cursor's advance.

e   = TBL[idx]                     # one dependent lookup ...
out += e.pattern (up to ~9 B)      # ... emits many bytes
cursors += e.nl, e.nr

8 · Demux kernels II — the K=2 endgame, five levers each measured before the next

Same problem as §7 — the K=2 literal re-interleave kernel — now tuned lever by lever with hardware counters. One question — “did we ever sweep the stream count?” — opened a day of counter-driven kernel work. 8.1 · Chain-count sweep — the inherited 8 was wrong almost everywhere

All K=2 kernels ran an 8-way chain interleave inherited from the original o1demux winner. Swept u2–u16 on all four platforms: optimum is 4 (Zen5 all files; Graviton4 5/6; M4 4–6) and 6 on GNR — worth 5–12% free. The u2 point proved the ~45–50-cycle pair recurrence is mostly hidden by just two chains; extra chains past 4 stretch per-chain latency (Zen5: 44 → 71 cycles) instead of raising IPC, and past ~6 the registers spill.

8.2 · k2g — the 2×16 B double-step

Load 16 B per side once, gather all 16 top bits per side once, run two full (6,6) table steps from registers: step 2’s index is just (gl>>nl1, gr>>nr1) of the same header words, so the second stream load and movemask drop off the chain (what killed k2d/k2e was paying the chained adjust and crippling the windows to (4,4); k2g keeps full yield and the same tables). Emit shuffles the 32 B {L16,R16} pair via vpermb-256 / vqtbl2q with per-lane +nl1/+nr1 pattern adjust. Won M4 and Zen5 on all 12 file-cells (−2–7%); lost GNR (−25–30%: vpermb+blendv on the serial path) and Graviton4 (−8%: four multiply-gathers per pair outweigh the saved load).

21 · Prior art — what exists, what’s ours

  • LZMA (2001): order-1 literals via top bits of previous byte (lc=3 default) — our K=8-by-top-bits, adaptive range coder, serial. Distance slots conditioned on length state = of|ml, shipped for 20+ years.
  • brotli (2015): clustered contexts + transmitted context map + merged histograms — our capacity- constrained clustering is a variant of its encoder machinery.

  • Still ours: cross-field sequence contexts with pre-decoded routing; the w-bits/state-chain analysis (slot = Markov memory); the demux kernel-geometry theory with cross-platform numbers; capacity-constrained remap for small K; the complete measured price list on zstd-parse streams.

what generalizes

22 · Laws & lessons

  • Yield per dependent lookup is the only lever: every kernel family bottoms at ~1.4 ns/lookup (M4) / ~3–3.7 ns (server cores); window bits are the merchandise and can’t be traded away.
  • Visibility economics: lookahead costs log₂K bits per element and must cover every bucket the walk can touch. K=2 is uniquely blessed; K=4 forces asymmetry; K≥8 belongs to scalar.
  • Conservation law: order-1 information flows through serial reconstruction, transmitted bits, or is surrendered — measured at every corner; segment cursor headers are the theoretically minimal payment (~0.01%).
  • The Huffman tree is a de-skewing transform — but only of marginals. Its routing bits are near-uniform residue order-0 (H₀ ≈ 0.997 b/bit, bias-only coding dead) while their serial structure survives untouched — the same bits pay 0.15–0.68 b/sym to order-k models (§1.1). Marginal skew and sequence structure are different resources. And the 1-bit floor recurses into any secondary coding layer, curable each time by canonical sub-bit tables.
  • The ANS slot carries the Markov memory — state = (symbol, slot), and the slot is a hash of the previous transition; symbol identity alone holds almost none of the lag-1 information.
  • Microarch traps: gcc compiles data-dependent ternaries to branches on x86 (mask-mux or die); 1 B/step walks from 4K-congruent starts alias catastrophically; equal-N lockstep segments stall on the fastest chain; M4 flatters latency-bound designs — verify on server cores before believing a chain trick.
  • Audit culture won the day: eight verdicts reversed by challenges — strawman baselines (bit-serial FSE, unclustered k2), missing costs (table build, headers), domain reality (PH-tree biases), platform transfer. The standing question: “what is the full cost, against what a competent engineer would actually build?”
  • The currency, final refinement (§8): at the optimal chain count every core sits at cycles/pair = instructions/pair ÷ an arch-specific effective-IPC wall (3.45–5.8 on this mix) — not load ports, not dispatch width, not (once ~2 chains run) chain latency. The only durable lever is instructions per decoded byte; serialization matters through its effect on the wall (GNR: 4.88 → 3.45 on the same data).
  • Count the scaffolding, not just the kernel: the step macro was ~15 instructions; the loop ran ~36. Field extraction, register spills, and per-chain guards each rivaled the semantic work — and each fell to a targeted fix (byte-packed meta + pext, fewer chains, cursor compaction) worth more than most kernel cleverness.

25 · Settled negatives — the do-not-re-explore registry

Additions from the 2026-08-24 exploration (older negatives live in the README digest and per-section verdicts; all were re-checked by the adversarial review round):

  • Brotli distance short codes (rep ±1..3 symbols): best case samba +20 KB (0.5%); mozilla NET −4 KB despite 30,445 hits (alphabet dilution). Near-miss offset repetition does not exist at L19.
  • Run-length symbols in the code-stream alphabets: loses to prev-sym order-1 in all 36 (file × stream) cells — run coding destroys the within-run context order-1 uses.
  • Parse-derived literal demux (run-role × pos%8 static classes): loses to the per-block baseline on both target files; the per-cell mass (~180 lits) can never pay static table headers.
  • Composition-coded bitmaps (n − log2 C(n,K)): closed-form ~7 finite-size bits per 16K root ≈ 2 B/block; the bias term is the empty p≈0.52 mass. Dead by Stirling, no probe needed.
  • ll/ml full-value dictionaries: best cell +1.6 KB, rest negative (0.1–3.3% of length symbols carry extras).
  • Serial recovery of the dictionary routing flag: order-1 recovers ≤ 4% of n·H₂(p); the ~100 KB order-1 structure on mozilla's merged stream is ordinary of|prev-of, available without the dictionary.
  • Float probability expansion in ctx builds: zero speed gain, ~1% of quad param sets drift the wire. Doubles stay.
  • kr entropy diet (§6): realizable but self-canceling against walk-layer decode cost.
  • 3-level (oct) fusion (§4.1): 3.8% of quad triples eligible, −1.36% of their bytes ≈ 0.01% of output, 8-cursor decode. Dead on applicability.
  • Fusion for order-0 nibble coding (§4.2): +1.63% worse corpus (lit x-ray +7.0%) — fusion's gain is all context, unreachable without carry-indexed tables.
