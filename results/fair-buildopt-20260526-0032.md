# fair sweep — decode-table build optimizations (2026-05-26, sha 19b5f00)

4-host sweep (m4 NEON, c6a Zen3 SSE, c8g Graviton4 NEON, c8i Xeon AVX-512),
MAIN datasets, best-of-5x10, ph table-G=128 KB, BLK=8192. Re-run after the
decode-table build rewrite (commits cf0f22d..f44b7f2): linearized the
O(maxlen*256) scans, dropped the O(N^2) flat recursion, stopped materializing
flat-subtree leaves (per-chunk build), min/max from length bins.

The build is per-window in the OPAQUE path (dec_op rebuilds the table inside
the timer); dec_pb uses a global prebuilt table. So the win lands on dec_op.

## Key effect: the opaque/prebuilt gap closed
The per-window table rebuild used to cost 25-50% of opaque ph decode
throughput; it is now near-free. On M4, dec_op/dec_pb for ph went from
~0.5-0.77 to ~0.89-1.07 (image_jpeg and json_api opaque now edge past
prebuilt, within noise). c8i shows the largest absolute gains.

## Non-ph engines unchanged (control)
td_*/huf0/fse/oodle are untouched by this work (td is the separate ph-td
codebase). m4/html_wiki: td_simdopt 2352->2429, huf0 2463->2335,
fse_x8y1 2018->1947 -- all within run-to-run noise.
