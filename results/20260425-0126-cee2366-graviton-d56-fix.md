# Graviton 4 D=5/D=6 fix — gate vqtbl{2,4} to Apple silicon

**Date:** 2026-04-25 01:26 UTC
**Commit:** [cee2366bb2372cd173e1900db0b5ea99f4c0c65b](../) (tip of main)
**Predecessor sweep:** [`20260424-2327-6762c55-full-sweep.md`](20260424-2327-6762c55-full-sweep.md) (commit 6762c55)
**Methodology:** 30 reps × 4M symbols, 5 runs (drop 2), `taskset -c 0` on Linux hosts.  All 20 roundtrip tests pass on every platform.

## Background

The previous full sweep ([6762c55](../)) flagged a regression on Graviton 4 (Neoverse-V2): the NEON D=5 and D=6 flat-subtree fast paths — using `vqtbl2q_u8` (32-byte c2s) and `vqtbl4q_u8` (64-byte c2s) — measured slower than the scalar `NEON_FLAT_UNPACK_SWITCH` fallback.  bell_s80 had dropped from a pre-TBL 1055 M/s to 526 M/s; flat_M5 1809→1282; flat_M6 1275→1194.

This commit gates the D=5/D=6 vector paths to `__APPLE__` only via build-time macro `PIVCO_NEON_FAST_MULTI_TBL`.  On non-Apple ARM (default), the cases fall through to `NEON_FLAT_UNPACK_SWITCH` — same scalar handling already used for D=7 and D≥8.

## Methodological note: c8g.large vs c8g.medium

This sweep upgraded the AWS Graviton 4 host from `c8g.medium` (1 vCPU, burstable) to `c8g.large` (2 vCPU, dedicated) so that benchmark variance is no longer host-noise-limited.  The 6762c55 sweep had a visible row-level CPU-steal hit on `geometric` (every external decoder column ~halved); on c8g.large, all 30-rep runs sit within the 5% spread band.

## Tried-and-rejected emulation

A first attempt replaced `vqtbl{2,4}q_u8` with explicit `2× vqtbl1` (or `4× vqtbl1`) + `vsub` + `vorrq` blends, with the idea that single-register TBL throughput is good on Neoverse-V2.  Result: bell_s80 went 537 → **458** M/s — *slower than the regressed multi-register path*.  Conclusion: the bottleneck on V2 isn't the TBL primitive specifically, it's that any vector path on these widths loses to scalar OoO-extracted parallelism over c2s lookups for the typical iteration counts.  Hence the simpler fix: gate off and let `NEON_FLAT_UNPACK_SWITCH` handle it.

The override macro `PIVCO_NEON_FAST_MULTI_TBL` allows future ARM uarchs that restore fast multi-register TBL to opt in via `-DPIVCO_NEON_FAST_MULTI_TBL=1`.
